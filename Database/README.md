# DiaMate veritabanı (PostgreSQL) – projede doğrudan kullanıma hazır

Bu klasör, `../Dataset/DiaMate_dataset.db` içindeki birleşik açık veri setini **ve** uygulamanın kendi veritabanı şemasını (kullanıcılar, hastalar, kayıtlar, uyarılar…) PostgreSQL'e kuran paketi içerir. Backend'i (Spring Boot) bu veritabanının üstüne yazacaksınız.

**Backend'in kullandığı veritabanı: Docker (port 5434)**

| | |
|---|---|
| Sunucu | `localhost:5434` (PostgreSQL 17, Docker konteyneri `diamate-postgres`, `../DiaMate/docker-compose.yml`) |
| Veritabanı | `diamate` |
| Kullanıcı | `diamate` (şifre `../DiaMate/.env` içinde, Git'e girmez) |
| JDBC | `jdbc:postgresql://localhost:5434/diamate` |
| pgAdmin | "DiaMate Docker (5434)" sunucu bağlantısı |

Bu paket 2026-09-30'da Docker veritabanına kuruldu (11 adım ve doğrulamalar geçti). Backend (`../DiaMate`) **yalnızca buna** bağlanır; kayıt, giriş gibi backend'in yazdığı her şey burada.

> **Mac'teki diğer PostgreSQL sunucuları (backend bunlara bağlanmaz):**
> - `5432`: Homebrew PG15 (içindeki `diamate_db` eskiden kalma, dokunulmadı).
> - `5433`: pgAdmin'in "PostgreSQL 18" sunucusu. Bu paketin **ilk kurulduğu yer**; artık yalnızca referans. Backend'in yazdıklarını içermez, Docker veritabanıyla zamanla farklılaşır.
>
> Proje raporu PG15 diyor: bu paket PG15 ve üstünde çalışır (PG18'de ve Docker'daki PG17'de tam kurulum test edildi).
>
> **Dikkat:** `docker compose down -v` Docker volume'unu, yani **tüm veriyi siler**. Olursa aşağıdaki "Docker veritabanına kurulum" adımlarıyla yeniden kurun.

### Tasarım kararları (backend'i kolaylaştırmak için)

- Rapordaki **PATIENT / DOCTOR / TREATMENT_PLAN / HEALTH_DATA / Reminder** tabloları karşılıklarıyla var: `patient_profiles`, `clinician_profiles`, `treatment_plans`, `glucose_logs` + `insulin_logs` + `meal_logs`, `reminders`. Rapordaki eksikler (paylaşım izinleri, denetim kaydı, çevrimdışı senkronizasyon, tekrar hatırlatma takibi) eklendi.
- Birincil anahtarlar `bigint GENERATED BY DEFAULT AS IDENTITY` → JPA'da `GenerationType.IDENTITY`.
- Enum'lar `varchar + CHECK` (JPA'da `@Enumerated(EnumType.STRING)`); izin verilen değerler sözlükte.
- Tüm zamanlar `timestamptz` (Java'da `Instant`). Glukoz her zaman **mg/dL** saklanır; mmol/L gösterimi `user_settings.glucose_unit` ile arayüzde yapılır.
- Çevrimdışı senkronizasyon için günlük tablolarında `client_uuid` (hasta başına benzersiz), `updated_at` (trigger otomatik günceller) ve `deleted_at` (soft delete) var.
- Şifreler **bcrypt** (`$2a$10$…`), Spring'in `BCryptPasswordEncoder`'ı doğrudan doğrular.
- ADMIN rolünün sağlık verisine örtük erişimi yoktur (gizlilik). Doktor/bakıcı erişimi yalnızca hastanın onayladığı (`ACTIVE`) ilişki ve izin bayrağıyla mümkündür (`fn_can_access`).
- `diamate_app` (backend) ve `diamate_readonly` (analiz / Dia servisi) rolleri hazır, ama **girişi kapalı** (şifre dosyalarda yok). Açmak için: `ALTER ROLE diamate_app LOGIN PASSWORD '...';`

## Docker veritabanına kurulum (backend'in kullandığı, önerilen)

Önce Docker veritabanını başlatın, sonra paketi kurun. Bağlantı bilgileri ve şifre `../DiaMate/.env` dosyasından okunur (ekrana yazılmaz):

```bash
cd "/Users/melihkocabyk/Desktop/Graduate Project/DiaMate"
docker compose up -d                                   # PostgreSQL 17, localhost:5434
set -a; . ./.env; set +a                               # POSTGRES_* değişkenlerini yükler
cd ../Database
PGPORT=$POSTGRES_PORT PGUSER=$POSTGRES_USER PGDATABASE=$POSTGRES_DB PGPASSWORD=$POSTGRES_PASSWORD \
  ./install_mac.sh                                     # BOŞ veritabanına kurar
```

Seçenekler aynı komutun sonuna eklenir: `--reset` (public + research şemalarını silip baştan kurar, **backend'in yazdığı veriler de silinir**), `--no-demo` (demo hesapsız).

## Başka bir PostgreSQL'e kurulum

`install_mac.sh`'in varsayılanı hâlâ pgAdmin'deki sunucudur: `localhost:5433`, veritabanı `diamate`, kullanıcı `postgres` (şifre sorulur, hiçbir yere yazılmaz). Başka bir sunucu için `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER` ortam değişkenlerini verin.

```bash
cd "/Users/melihkocabyk/Desktop/Graduate Project/Database"
./install_mac.sh --reset        # 5433'e: public + research şemalarını silip baştan kurar (~20 sn)
```

pgAdmin'den (hangi sunucuya bağlıysanız ona kurar): `diamate` → sağ tık → *PSQL Tool* → `\i '/Users/melihkocabyk/Desktop/Graduate Project/Database/sql/reset_and_run_all.sql'`

CSV dosyaları `../Dataset/unified/` (12 tablo) ve `data/` (timeline, sources) içinden okunur: `Dataset` ve `Database` klasörleri yan yana kalmalı.

> **Kurulumdan sonra:** Bu paket şemanın **V1** halini kurar. Backend (`../DiaMate`) ilk açıldığında **Flyway** sonraki değişiklikleri (`DiaMate/src/main/resources/db/migration/V2__...sql` ...) otomatik uygular. Örneğin V2 ile `users.full_name` ikiye bölündü (`first_name`, `last_name`) ve `date_of_birth`, `gender` `users`'a taşındı. Ayrıntı: `docs/BACKEND_NOTES.md` → "Şema değişikliği".

Kurulum sonunda `11_verify.sql` otomatik çalışır: araştırma tablolarının satır sayıları CSV'lerle birebir mi, yetim kayıt var mı, erişim kuralları doğru mu, demo şifreleri çalışıyor mu. Bir şey yanlışsa hata verip durur.

## Dikkat edilmesi gerekenler

- **Besin değerleri tahmindir.** `food_classes.*_est` ve `food_catalog` sütunları genel bilgiden yaklaşık yazıldı, ölçülmüş değil (`is_verified = false`). Ekranda "yaklaşık" diye gösterin, **insülin dozu hesabında kullanmayın**.
- **BrisT1D tarihleri gerçek değil** (2000-01-01'den başlayan göreli çizelge). Gerçek takvim tarihi gereken analizde `time_basis = 'real'` süzün.
- **HUPA-UCM birimleri çıkarıldı:** bazal hız 5 dakikalık birim kabul edilip ×12 ile U/saat yapıldı, `carb_input` gram kabul edildi. Kaynak birimi açıkça yazmıyor.
- **Shanghai voglibose dozları:** kaynakta "0,2 g" yazıyor, gerçekte büyük ihtimalle 0,2 mg. `research.oral_medications` kaynağa sadık bırakıldı (200 mg görünür), demo seed bu değerleri boş bırakır.
- **Demo hastaların cinsiyet/yaş/boy/kilo/hastalık süresi** HUPA-UCM ve UC_HT kaynaklarında yoktur: 5 hasta için **sentetik** değerler kullanıldı. Shanghai hastalarınki kaynaktandır (yaş yaklaşık doğum yılına çevrildi).
- **Lisanslar:** Shanghai (Figshare), BRFSS (CDC/Kaggle) ve HUPA-UCM (Mendeley) için lisans metnini kaynak sayfasından doğrulayın. UC_HT_T1DM GitHub'da lisanssız: dağıtmadan önce yazarlara sorun. BrisT1D Kaggle yarışma kurallarına, Food-101 araştırma/ticari olmayan kullanıma tabidir. Ayrıntı `research.sources` tablosunda.
- **CGMacros** (fotoğraflı öğün + CGM) eklenemedi: PhysioNet bu ortamdan engelli. Elle indirilirse `Dataset/sources/raw/CGMacros/` altına konup eklenebilir.
- Bu veriler teşhis/tedavi için değildir, yalnızca yazılım geliştirme ve test içindir.
